# お知らせの登録の手順 (運営向け)

この文書は、運営がお知らせを `announcements` テーブルに直接登録するときの手順です。お知らせの登録画面はないため、SQL で登録します。登録の条件と、公開日時の書き方を守ってください。

## 1. 接続

マイグレーション用の利用者 `app_owner` で接続します。アプリケーション用の利用者 `app_user` は `announcements` の `SELECT` だけを持つため、登録、変更、削除はできません。`app_user` で登録しようとすると、次のエラーになります。

```text
ERROR:  permission denied for table announcements
```

開発の環境では、`docker compose` で起動した PostgreSQL に、コンテナの中の `psql` で接続します。リポジトリのルートで、次のコマンドを実行します。

```bash
docker compose exec postgres psql -U app_owner -d app
```

コンテナの中から接続するため、パスワードは入力しません。複数の行にわたる SQL は、末尾の `;` を入力すると実行されます。

## 2. 登録の条件

| 項目 | 条件 |
| --- | --- |
| タイトル | 1 文字以上 100 文字以内 |
| 本文 | 1 文字以上 2,000 文字以内。改行を含めてもかまいません |
| 公開日時 | 必須。タイムゾーンを含めて書きます (3 を参照) |

- 文字数は、Unicode の符号位置の数で数えます。全角、半角、改行は、それぞれ 1 文字です。
- 文字数は `char_length` で確かめられます。たとえば、`SELECT char_length('お知らせ');` は `4` を返します。
- データベースは、文字数を検査しません。条件を外れた値も登録されます。この機能も条件を検査せず、条件を外れたお知らせを、登録されたまま表示します。登録の前に、条件を守っているか確かめてください。

## 3. 公開日時の書き方

公開日時は、`YYYY-MM-DDThh:mm:ss` の後に、`Z` または `±hh:mm` を必ず付けて書きます。次の例は、日本時間 (+09:00) の 2026 年 10 月 12 日 9 時です。

```sql
'2026-10-12T09:00:00+09:00'
```

UTC で書く場合は、`Z` を付けます。たとえば、`'2026-10-12T00:00:00Z'` は、上と同じ時点です。

ずれ (`Z` や `±hh:mm`) の無い書き方は、データベースが登録を拒否します。

- `'2026-10-12T09:00:00'` (ずれが無い)
- `'2026-10-12 09:00:00+09:00'` (`T` の代わりに空白)

これらを登録すると、次のエラーになります。

```text
ERROR:  new row for relation "announcements" violates check constraint "announcements_published_at_text_format"
```

公開日時は必須です。`NULL` は登録できません。存在しない日付 (例: `'2026-02-30T00:00:00Z'`) も拒否されます。

表示と並び順は、次のように決まります。

- 公開日は、日本時間の年月日で表示されます。たとえば、公開日時が `'2026-10-11T23:00:00Z'` のお知らせは、日本時間では 2026 年 10 月 12 日 8 時なので、公開日は `2026年10月12日` と表示されます。
- 並び順は、公開日時 (時刻まで) で決まります。同じ日付でも、時刻が後のお知らせが先に並びます。

## 4. 登録の SQL

基本の形は、次のとおりです。

```sql
INSERT INTO announcements (title, body, published_at_text)
VALUES ('メンテナンスのお知らせ', '10 月 20 日 2 時から 4 時まで、サービスを停止します。', '2026-10-12T09:00:00+09:00');
```

`id` と `published_at` は指定しません。`id` は自動で採番されます。`published_at` は `published_at_text` から導かれる値のため、指定するとエラーになります (例: `cannot insert a non-DEFAULT value into column "id"`)。

改行を含む本文は、文字列の中で改行して書きます。改行の位置と数が、そのまま本文に登録されます。

```sql
INSERT INTO announcements (title, body, published_at_text)
VALUES (
    '新機能の案内',
    'お知らせの一覧を追加しました。

詳しくは、次の案内をご覧ください。',
    '2026-10-12T09:00:00+09:00'
);
```

`'...'` の中に `\n` と書くと、改行ではなく `\` と `n` の 2 文字として登録されます。`\n` で改行を書く場合は、`E'...'` の形で書きます。

```sql
INSERT INTO announcements (title, body, published_at_text)
VALUES ('新機能の案内', E'お知らせの一覧を追加しました。\n\n詳しくは、次の案内をご覧ください。', '2026-10-12T09:00:00+09:00');
```

本文に `'` (シングルクォート) を含む場合は、`''` と 2 つ続けて書きます (例: `'お知らせ''一覧'`)。

## 5. 予約投稿

公開日時を未来の日時にすると、その日時になるまで表示されません。予約のための特別な操作は要りません。サーバーの再起動も不要です。

```sql
INSERT INTO announcements (title, body, published_at_text)
VALUES ('10 月 20 日のメンテナンス', '10 月 20 日 2 時から 4 時まで、サービスを停止します。', '2026-10-19T18:00:00+09:00');
```

- 公開日時と同じ時点になると、利用者が一覧を開いたときから表示されます。
- 公開前のお知らせは、一覧の件数にも並び順にも含まれません。

## 6. 変更と取り消し

変更するお知らせの `id` は、次の SQL で確かめます。

```sql
SELECT id, title, published_at_text FROM announcements ORDER BY id;
```

公開日時を変更する例です。`1` は、確かめた `id` に置き換えてください。

```sql
UPDATE announcements SET published_at_text = '2026-10-20T09:00:00+09:00' WHERE id = 1;
```

- `WHERE` を付けないと、すべてのお知らせが変わります。必ず `id` を指定してください。
- 公開日時は、タイムゾーンを含めて `published_at_text` に書きます (3 を参照)。`published_at` は生成列のため、直接変更できません。
- タイトルや本文を変えるときは、`SET title = '...'` や `SET body = '...'` を使います。

お知らせを非表示にする方法は、次の 2 つです。

- 公開日時を未来の日時にする: 公開中のお知らせは、公開前に戻ります。表示を再開するときは、公開日時を過去か現在の日時に戻します。

```sql
UPDATE announcements SET published_at_text = '2030-01-01T00:00:00+09:00' WHERE id = 1;
```

- 削除する: 行を消します。削除したお知らせは、SQL では元に戻せません。

```sql
DELETE FROM announcements WHERE id = 1;
```

変更や取り消しは、利用者が一覧を開き直したときに反映されます。一覧を開いたままの画面は、更新されません。

## 7. 登録後の確認

登録した内容を、SQL で確かめます。

```sql
SELECT
    id,
    title,
    char_length(title) AS title_length,
    char_length(body) AS body_length,
    published_at AT TIME ZONE 'Asia/Tokyo' AS published_at_jst
FROM announcements
ORDER BY published_at DESC, id DESC;
```

- `title_length` が 1 以上 100 以下、`body_length` が 1 以上 2,000 以下であることを確かめます。
- `published_at_jst` は日本時間の日時です。意図した日時になっているか確かめてください。
- 同じ公開日時のお知らせは、後に登録したものが先に並びます。この SQL の並び順は、一覧と同じです。

一覧の画面でも確かめます。バックエンドを起動した状態で、`https://localhost:8443/announcements` を開きます (起動の手順は `backend/README.md` を参照)。画面を開き直すと、最新の内容が表示されます。

公開中のお知らせが 21 件以上あると、一覧に表示されるのは新しい順の 20 件だけです。いちばん古いお知らせは表示されませんが、削除されたわけではありません。

## 8. 注意

- タイトルと本文に HTML を書いても、解釈されません。タグは文字としてそのまま表示されます (例: `<script>` を含む本文は、スクリプトとして動かず、文字で表示されます)。
- URL は、リンクになりません。文字としてそのまま表示されます。
